### 🔐 **PHASE 2 – Admin Authentication System**

#### 🔹 Main Admin Login
- Implemented secure JWT-based login for the **main admin**
- Passwords hashed with bcrypt; tokens saved in `localStorage`

#### 🔹 Admin Registration & Approval Flow
- Admins register with email → marked as `isApproved: false` by default
- Main admin views pending list and can:
  - ✅ Approve → sets `isApproved: true`
  - ❌ Deny → deletes the admin from DB
  - 🔁 Revoke → sets `isApproved: false`

#### 🔹 Role-Based Access Control & Navigation
- Role stored in JWT; decoded and used on frontend
- Dynamic navigation menu:
  - **User:** Home, View Problems, Login, Register, Theme Toggle  
  - **Admin:** Dashboard, View Problems, Manage Problems, Logout  
  - **Main Admin:** Dashboard, View Problems, Manage Problems, Manage Admins, Logout

### 📚 **PHASE 3 – Problem Management System**

#### 🔹 Backend – Dynamic MongoDB per Rating
- Each problem rating (e.g., `800`, `900`, etc.) stored in its own collection
- Problem schema: `Name`, `Link`, `Tags`, `Level`, `Knowledge`, `addedBy`, `deleteRequested`

#### 🔹 Problem Routes
```js
// 🔹 Add a problem (admin only)
POST    /problems/:rating                     → addProblem()

// 🔹 Get problems by rating (public)
GET     /problems/:rating                     → getProblemsByRating()

// 🔹 Update problem by ID (admin only)
PUT     /problems/:rating/:id                 → updateProblem()

// 🔹 Request deletion (admin only)
DELETE  /problems/:rating/:id                 → requestDeleteProblem()

// 🔹 View pending deletions (main admin only)
GET     /problems/pending-deletions/:rating   → getPendingDeletes()

// 🔹 Approve and delete (main admin only)
DELETE  /problems/approve-delete/:rating/:id  → approveDeleteProblem()

// 🔹 Deny delete request (main admin only)
PATCH   /problems/deny-delete/:rating/:id     → denyDeleteProblem()
```

> 🔐 All routes protected with `verifyToken`, and some restricted via `requireMainAdmin`
